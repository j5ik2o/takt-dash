このディレクトリは、taktDash のフロントエンドである Next.js アプリを置く場所です。

このアプリは、バックエンドの gRPC API から取得した状態を画面に表示する BFF 構成です。
Next.js のサーバー側（RSC と Route Handlers）が gRPC クライアントとしてバックエンドへ接続し、
ブラウザはバックエンドへ直接接続しません。gRPC-Web も使いません。

## 画面

- 概要（`/`）: サーバーの読み取り状態と最終読み取り時刻、プロジェクト、走っている run、判断待ちの件数、閾値
- プロジェクト（`/projects`）: プロジェクトごとのゴール・タスク・run・判断待ち
- 判断待ち（`/decisions`）: 未回答の問い合わせと人のマージ待ちのゴールの一覧（表示のみ）
- アクティビティ（`/activity`）: 出来事の一覧と7日分の日次集計、サーバーごとの当日の件数
- run 詳細（`/runs/[slug]`）: メタデータ、ステップ、ログの末尾、レポート、指示書、今のステップ

開いている画面は、バックエンドの `WatchState`（サーバーストリーミング）を `/api/state` が SSE に
中継したものを受けて自動更新します。切断時は再接続します。

## 開発サーバーを起動する

開発サーバーを起動するには、次のコマンドを実行します。

```bash
npm run dev
```

開発サーバーを起動したら、ブラウザで http://localhost:3000 を開くと、画面を確認できます。

## バックエンドへの接続先を設定する

接続先は環境変数 `TAKTDASH_BACKEND_ADDR` で指定します。未設定のときは `127.0.0.1:50051` を使います。

```bash
TAKTDASH_BACKEND_ADDR=127.0.0.1:50051 npm run dev
```

バックエンドに接続できないときも、ページは落ちずに「backend に接続できません」と表示します。

## 書き込みを許可するホストを設定する

判断待ちの書き込み API は、ブラウザが送る Origin ヘッダのホストと Host ヘッダを比べます。
両者が一致し、そのホストが許可の一覧にあるときだけ、API は書き込みを受け付けます。
許可の一覧は環境変数 `TAKTDASH_ALLOWED_HOSTS` で指定します。

- 形式: `host:port` をカンマで区切って並べます（例: `localhost:53580,127.0.0.1:53580`）。
  前後の空白は取り除かれ、大文字と小文字は区別されません。`http://` やパスを付けた値は無効となり、一覧から除かれます。
- 未設定のとき、または空白だけのとき、API は次の4つのホストを許可します:
  `10.0.1.143:3000`、`100.106.166.1:3000`、`127.0.0.1:3000`、`localhost:3000`。
- 値を設定すると、その値が既定の一覧を置き換えます。既定の一覧に追加されるわけではないので、
  既定のホストも使うときは、それらも値に含めてください。
- API は、次の要求を 403 で拒否します。
  - 一覧に無いホストからの要求
  - Host ヘッダと Origin ヘッダのホストが一致しない要求
  - `sec-fetch-site: cross-site` が付いた要求
- Origin ヘッダの無い要求（CLI など）は照合の対象外で、API は一覧に関係なく受け付けます。
- フロントエンドはこの値をリクエストのたびに読みます。

3000 以外のポートで起動してブラウザから書き込むときは、同じポートを一覧に設定します。

```bash
TAKTDASH_ALLOWED_HOSTS=localhost:53580,127.0.0.1:53580 npm run dev -- --port 53580
```

## 実バックエンドへの接続確認（任意）

実バックエンドと実 takt-mcp を起動した環境での表示確認は、明示的に行う任意の手順です。

1. バックエンドを起動します。
2. 次のコマンドで開発サーバーを起動します。

   ```bash
   TAKTDASH_BACKEND_ADDR=127.0.0.1:50051 npm run dev
   ```

3. ブラウザで http://localhost:3000 を開き、概要ページに実プロジェクトの状態が表示されることを確認します。

この手順は環境変数を明示したときだけ使います。テストはダミー gRPC サーバーで動くため、
実バックエンドが無くても型検査と lint とテストは通ります。

## 検査を実行する

次のコマンドで、型検査と lint とテストを実行します。

```bash
npm run typecheck
npm run lint
npm run test
```

テストは `node --test` で実行します。生成コードの enum を含む TypeScript をそのまま読み込むため、
`--experimental-transform-types` と `.tsx` を変換する解決フックを使います。

## 見た目の退行を防ぐ（スクリーンショット比較）

`docs/taktdash.html` をデザインの基準とし、実装の画面を同じ幅で撮って並べ、差分を確認します。

1. バックエンドと開発サーバーを起動します（`TAKTDASH_BACKEND_ADDR=127.0.0.1:50051 npm run dev`）。
2. ブラウザの開発者ツールで、表示幅を 1440px、1024px、375px に切り替えます。
3. 各幅で `/`、`/projects`、`/decisions`、`/activity`、`/runs/[slug]` の5画面を撮影します。
4. 同じ画面を `docs/taktdash.html` のモックでも開き、同じ幅で撮影して並べます。
5. 次の観点で差分を確認します。
   - 状態（実行中・ログ停止・応答なし・一時停止）が色で区別できるか
   - サイドバーの現在ページが淡い緑で強調され、他のページでは強調されないか
   - 1024px でサーバーのカードが1列になり、run 行の状態・本文・進捗の列が揃うか
   - 375px で横スクロールが出ないか
   - 時刻・識別子が等幅で表示されるか
6. 差分があれば `frontend/web/app/globals.css` の値を直し、再度撮影します。

### 実施状況

このリポジトリにはブラウザ自動化が入っていないため、この手順は**未実施**です。
実ブラウザでの 375px / 1024px の実測とスクリーンショット比較は行っていません。

## API の正

API の正はリポジトリの `proto/taktdash.proto` です。TypeScript の生成物は次のコマンドで再生成し、
手で編集しません。

```bash
npm run proto:generate
```
