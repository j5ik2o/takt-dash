# takt-dash-cli

`takt-dash-cli` は、taktDash のバックエンド（`takt-dash-backend`）の gRPC へ接続し、概要の閲覧と、
問い合わせへの回答・プルリクエストのマージ依頼・ゴール登録の承認待ちの一覧・承認・却下を行う
コマンドです。

## 起動方法

ワークスペースのルートでビルドし、生成された実行ファイルを起動します。

```sh
cargo build -p takt-dash-cli
./target/debug/takt-dash-cli overview
```

位置引数を省略した場合も `overview` として動作します。

```sh
./target/debug/takt-dash-cli
```

## コマンド

```text
takt-dash-cli overview [--addr <待ち受けアドレス>] [--config <設定ファイル>]
takt-dash-cli answer --goal <ゴールID> --question <問い合わせID> (--text <本文> | --report completed|unable)
takt-dash-cli merge --goal <ゴールID> --yes
takt-dash-cli registrations [--project <プロジェクト名>]
takt-dash-cli approve-registration --project <プロジェクト名> --revision <リビジョン> --yes
takt-dash-cli reject-registration --project <プロジェクト名> --revision <リビジョン> --yes
```

- `answer` は問い合わせへ回答します。`--text` に本文を渡すか、`--report completed`（完了）または
  `--report unable`（対応不能）で報告します。
- `merge` はゴールのプルリクエストのマージを依頼します。
- `registrations` はゴール登録の承認待ちを一覧表示します。種別は `[ゴール登録の承認待ち]` と表示し、
  問い合わせ（質問）とは区別します。`--project` を省略すると設定の全プロジェクトを対象にします。
- `approve-registration` / `reject-registration` はリビジョンを指定してゴール登録を承認・却下します。
- 破壊的な操作（`merge`・`approve-registration`・`reject-registration`）には `--yes` が必要です。
  無い場合は実行せず、使い方を標準エラーへ表示して終了コード 2 で終わります。

回答に使う問い合わせ ID は、`overview` の判断待ちの問い合わせ行に `問い合わせID:` として表示されます。
回答・マージ依頼に使うゴール ID は、ゴールに属する判断待ちの行に `ゴールID:` として表示されます。

## 引数

| 引数 | 説明 |
|------|------|
| `overview` | 概要を表示します。位置引数を省略した場合の既定の動作です。 |
| `answer` | 問い合わせへ回答します。 |
| `merge` | プルリクエストのマージを依頼します。 |
| `registrations` | ゴール登録の承認待ちを一覧表示します。 |
| `approve-registration` | ゴール登録を承認します。 |
| `reject-registration` | ゴール登録を却下します。 |
| `--goal <ゴールID>` | 回答・マージ依頼の対象のゴール ID を指定します。 |
| `--question <問い合わせID>` | 回答する問い合わせの ID を指定します。 |
| `--text <本文>` | 回答の本文を指定します。 |
| `--report <completed\|unable>` | 回答の報告の種類を指定します。 |
| `--project <プロジェクト名>` | 一覧・承認・却下の対象プロジェクトを指定します。 |
| `--revision <リビジョン>` | 承認・却下するゴール登録のリビジョンを正の整数で指定します。 |
| `--yes` | 破壊的な操作の確認フラグです。 |
| `--addr <待ち受けアドレス>` | 接続先の待ち受けアドレスを指定します（例: `127.0.0.1:50051`）。 |
| `--config <設定ファイル>` | バックエンドと同じ形式の設定ファイルのパスを指定します。`listen` を接続先に使います。省略時は `taktdash.config.json` を読みます。 |
| `--help` / `-h` | 使い方を表示します。 |

コマンドごとに使えるフラグは決まっています。未知のコマンド・未知の引数・必須引数の不足・不正な値は、
使い方を標準エラーへ表示して終了コード 2 で終わります。

## 終了コード

| 終了コード | 意味 |
|------------|------|
| `0` | 成功しました。 |
| `1` | バックエンドへ接続できない、またはバックエンドが操作に失敗しました。 |
| `2` | 使い方の誤りです（未知のコマンド・引数、必須引数の不足、不正な値、`--yes` の不足）。 |

## 表示する内容

概要の表示には、バックエンドの gRPC の `TaktDashService.GetOverview` が返す `DashboardState` を使います。
次の項目を日本語で表示します。

- 最後に読めた時刻
- サーバーごとの名前・機種・接続状態（接続中／応答なし）と台数
- プロジェクトの一覧（名前と説明）と件数
- ゴールの一覧（プロジェクト・ゴール ID・名前）と、タスクの状態ごとの件数（完了・失敗・未着手・実行中）
- run の一覧（プロジェクト・タスク名・要約）と、実行中の run の件数
- 判断待ちの件数と内訳（未回答の問い合わせ・人のマージ待ち）と、その一覧（種別と本文）。ゴールに属する行には `ゴールID:` を、問い合わせの行には回答に使う `問い合わせID:` も表示します
- 異常判定の閾値（判断待ちの滞留の分数とログの無音の分数）

一覧が空の項目は「（なし）」と表示します。

## 接続先の解決順

接続先は次の順で解決し、最初に見つかった値を使います。空文字列の値は未設定として扱います。

1. コマンドライン引数の `--addr`
2. 環境変数 `TAKTDASH_BACKEND_ADDR`（`frontend/web` と同じ名前です）
3. `--config` で指定した設定ファイル（省略時は `taktdash.config.json`）の `listen`
4. 既定値 `127.0.0.1:50051`（バックエンドの待ち受けの既定値と同じ値です）

`--addr` などの値が待ち受けアドレスとして解釈できない場合は、既定値へ置き換えず、標準エラーへ理由を表示して終了コード 2 で終わります。

設定ファイルの `listen` は、バックエンドの設定ファイルと同じキーです。新しい独自の設定形式は使いません。

## 接続できないとき

バックエンドへ接続できないときは、接続できない旨と接続先を日本語で標準エラーへ表示し、終了コード 1 で終わります。
接続不能とみなすのは、接続自体に失敗したとき、および接続先が gRPC として応答しないとき（gRPC のステータスが `UNAVAILABLE`・`DEADLINE_EXCEEDED`・`CANCELLED`・`UNKNOWN` のとき）です。
待ち受けはあるが gRPC を話さない相手（接続後に切断する、応答しないなど）は、`CANCELLED` または `UNKNOWN` として同じ分類になります。
この 4 コードは、`frontend/web` の `BackendUnavailableError` が接続不能とする 2 コード（`UNAVAILABLE`・`DEADLINE_EXCEEDED`）より広い集合であり、CLI と web で接続不能とみなす範囲は同じではありません。
バックエンドが応答したうえで概要を返せなかった場合は、接続不能ではなく「概要を取得できませんでした」として区別して表示します。これは `NOT_FOUND`・`PERMISSION_DENIED`・`INTERNAL` など、上記の 4 コード以外の gRPC ステータスすべてに当てはまります。
標準出力へは概要を表示しません。

書き込みコマンドでも同じ接続不能の分類を使います。バックエンドが応答したうえで操作に失敗した場合は、
接続不能ではなく `backend から<操作名>に失敗しました（<gRPC ステータス>）。<メッセージ>` として区別して
表示し、標準出力へは結果を出しません。道具の失敗（前提不一致など）は `FAILED_PRECONDITION` で返ります。
