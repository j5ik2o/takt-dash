# issue #421 の設計：Web のエラーの照合の 500 を HTTP の状態の形だけにする

対象の issue：[j5ik2o/takt-dash#421](https://github.com/j5ik2o/takt-dash/issues/421)。

## いまの状態（main `4361f96`）

`WEB_ERROR_RE = error|Error|ERR_|500`（`tools/prod-check/prod_log.py:15`）は、本文のどこかの `500` に当たる。`✓ Ready in 500ms`、`1500ms`、`5000`、`duration_ms=500.81`（本番の `web-launchd.log` に実際にある `[taktDash][timing]` の行）がエラーに数えられる。本番の `web-launchd.err.log`（2026-11-27 時点、1023 行）には `500` を含む行が無く、エラーの行は `⨯ Error: …` と `Error: listen EADDRINUSE …` だけだった。HTTP の 500 の形は、テストの固定例の `GET /api/state 500` だけ。

## 何をどう変えるか（`prod_log.py` の `WEB_ERROR_RE` の 1 行だけ）

```python
WEB_ERROR_RE = re.compile(
    r"error|Error|ERR_|(?:(?:^|(?<=[\s(\[\"']))|(?i:status|code)[\"']?\s*[:=]\s*)500(?=$|[\s)\]}\"',;]|\.(?!\d))"
)
```

- `500` は、前が「行頭、空白、`(`、`[`、`"`、`'`」のとき、または直前が `status`・`code` の形（大文字と小文字は問わない。`statusCode`、`http_status`、`status_code` も含む。任意の `"`・`'` と空白を挟んで `:` または `=` が続く）のときだけ当たる。素の `:` は前の区切りに含めない（`{"duration_ms":500}` を HTTP の形と区別するため）。後ろが「行末、空白、`)`、`]`、`}`、`"`、`'`、`,`、`;`、数字以外の文字が続く `.`」のときだけ当たる。`.` の次が数字のとき（`500.81` の `.`）は区切りとして扱わない。
- 当たる例：`GET /api/state 500`、`500 Internal Server Error`、`HTTP/1.1 500`、`status=500`、`statusCode=500`、`http_status=500`、`status_code=500`、`status: 500`、`(500)`、`[500]`、`{"status":500}`、`... status 500.`、`500, …`、本文が `500` だけ。
- 当たらない例：`{"duration_ms":500}`、`{"count":500}`、`{"ms":500}`、`500ms`、`1500ms`、`5000`、`5001`、`500.81`、`0.500s`、`duration_ms=500`、`ms=500`、`1,500`、`x500y`、`500件`。
- `error`・`Error`・`ERR_` の照合、Ready の切り出し、本文を鍵にした集約、表示は変えない。

## 変えないこと（範囲の外）

backend のログの節（照合・集約・表示）、`split_stamp`、`web_error_groups` の切り出しと集約、`log_excerpts` の形、`prod_check.py`、`Makefile`（`prod_log_test.py` は `make test` にもう入っている）。全角の括弧（`（500）`）は新しい規則では当たらない（main では当たっていた）。空白を挟んだ単位（`500 ms`）は HTTP の形として当たる側に残る。どちらも今のログに出ていないので、この issue では扱わない。

## 守る不変条件

- I1：`error`・`Error`・`ERR_` のどれかを含む本文は、今と同じくエラーになる。
- I2：時刻の無い今の固定例（`UNSTAMPED_WEB_LOG`）の `log_excerpts` の出力は、1 文字も変わらない（`GET /api/state 500（2 件）` も残る）。
- I3：エラーの判定は本文だけで決まる（#409 の I2）。判定が変わるのは、`500` だけを理由にエラーになっていた行だけ。

## 性質（PBT、除外なし。`random` の種つき）

- P3：エラーの語（`error`・`Error`・`ERR_`）と HTTP の 500 の形を含まない埋め草に、ms などの数の形（`{n}ms`、`{n}.{d}ms`、`in {n}ms`、`{n}.{d}s`、`duration_ms={n}`、`duration_ms={n}.{d}`、`ms={n}`、`{n}`）を混ぜた行だけのログは、エラーの組を 1 つも出さない。数の形（単位や小数点以下が付く形）は `n` に 500 を含めてよい。裸の `{n}` だけは 500 を除く（`{n}` は 500 以外の任意の数で、`1500`・`5000` のように 500 の前後に数字が続く数も含む）。埋め草は数字・`=`・`r`・`R` を使わない文字で作る（エラーの語と HTTP の形を偶然に作らないため。性質の定義域で、除外ではない）。
- P4：任意の埋め草（数字・日本語・記号を含む）の間に、空白を挟んで HTTP の 500 の形（上の「当たる例」）を 1 つ置いた行は、必ずエラーの組に入る。
- P2（#409 の性質）の参照の実装の照合を、上の新しい規則に書き換える。

## 壊しうる入力

`500` が行頭・行末、`500` の前後が数字・小数点・`=`・`,`・アルファベット・日本語、数字以外の文字が続く `.`（`500.foo`）、`status=` と `ms=` の違い、大文字の `Status=`・`STATUS=`、時刻の `.500Z`（#409 で外している）、`500` が 2 つ以上ある行、`500500`。

## 影響

上流・保存済みデータ・公開 API（proto）・守りの仕組み（CI の定義、ルールセット）には触れない。prod-check の出力の Web の節から、`500` の数だけでエラーになっていた行が消える。状態遷移は無い（1 行ずつの正規表現の照合だけ）ので Quint は書かない。
