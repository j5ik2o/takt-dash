# issue #307 の設計：切断中は判断待ちの回答ボタンを押せないようにする

対象の issue：[j5ik2o/takt-dash#307](https://github.com/j5ik2o/takt-dash/issues/307)
PR：[j5ik2o/takt-dash#381](https://github.com/j5ik2o/takt-dash/pull/381)

実装が先に進んでいたため、出来上がった時点の設計を書きます。

## 何をどう変えたか

切断中も、最後に読めた判断待ちの一覧は残ります（[j5ik2o/takt-dash#378](https://github.com/j5ik2o/takt-dash/pull/378) 以前から判断待ちのページはそうでした）。そのままだとボタンを押せて、書き込みを送れてしまいます。そこで、ボタンを無効にする条件を「送信中」から「送信中か切断中」に広げます。

- `DecisionsContent` がすでに持っている `disconnected` を、`DecisionActions` → `DecisionActionsView` へ渡す。`disconnected` の出どころは SSE の状態（`reduceLiveState`。エラーで true、次の状態を受け取ると false）で、新しい状態は持たない。
- 切断中に無効にする要素：選択肢のボタン、自由記述の入力欄と「回答する」、作業の報告（実施した・対応できない）、確認を開くトリガー（マージを承認・承認・却下）、確認ダイアログの確定ボタン。
- 切断中も押せる要素：確認ダイアログの「やめる」。閉じるだけで何も送らないため。送信中は従来どおり押せない。
- 操作のある項目ごとに「再接続するまで操作できません。」（`p.note`）を添える。確認ダイアログが開いていれば、ダイアログの中にも出す。
- 再接続すると `disconnected` が false に戻り、押せる状態に戻る。
- フォーカス：
  - 切断で確定ボタンが無効になったとき、そこにフォーカスがあればダイアログの見出しへ移す（Cursor Bugbot の指摘）。「やめる」やリンクにあるフォーカスは動かさない。
  - 切断中にダイアログを閉じたら、トリガーが押せないので、フォーカスの復帰を待つ。復帰の判定（`decideDialogRestore`）を `disconnected` の変化でも走らせ、再接続でトリガーへ戻す。
- aislop の重複ブロックの検出に当たったため、`merge` と `goal-registration` の描画を 1 つの case にまとめた（挙動は同じ）。

### 変えないこと・範囲の外

- 送信中に切れた書き込みは止めない。結果が返るまで待つ（backend へ届いた書き込みは backend が最後まで実行する）。
- ボタンが 1 回で取り消せない件（[j5ik2o/takt-dash#308](https://github.com/j5ik2o/takt-dash/issues/308)）は扱わない。
- 「操作に必要な値が欠けた」項目（`unavailable`）はもともとボタンが無いので変えない。理由の文も出さない。
- 書き込みの API（`/api/decisions/*`）の側では接続の有無を見ない。画面の切断（SSE）と書き込みの成否は別で、SSE だけ切れて書き込みは通る場合もあるが、最後に読めた内容が古い可能性があるため、画面では止める。API 側の古さの検査は issue #319 の照合が担う。
- 待ち受けの設定、接続元の制限は触らない。

## 守る不変条件

1. 切断中の画面からは書き込みを送らない（送信につながる要素はすべて無効）。
2. 「やめる」は送信中だけ無効で、切断では無効にしない。
3. 理由の文は、切断中で、操作のある項目にだけ出る。
4. 無効なボタンにフォーカスが残らない。ダイアログが開いている間、フォーカスはダイアログの中にある。
5. 切断中に閉じたダイアログのフォーカスは、再接続でトリガーへ戻る。
6. 再接続したら、接続中と同じ操作ができる（無効の条件は `busy || disconnected` だけで、切断の履歴を持たない）。

## PBT の性質

ライブラリ（fast-check など）は入っていないため、入力の領域が有限なことを使い、全組み合わせを列挙します（`frontend/web/test/components/decision-actions.test.ts` の「性質: …」）。除外はありません。

- 領域：フィクスチャの判断待ちすべて（選択肢付きの質問、自由記述の質問、作業の依頼、マージ待ち、URL の無いマージ待ち、ゴール登録、値の欠けた項目など）× 開いているダイアログ（その種別で開けるものすべてと閉じた状態）× 送信中 {偽, 真} × 切断 {偽, 真} × 入力 {空, 非空}。
- 性質：
  - 「やめる」の disabled ⇔ 送信中。
  - 「回答する」の disabled ⇔ 送信中 ∨ 切断 ∨ 入力が空。
  - それ以外のボタンと入力欄の disabled ⇔ 送信中 ∨ 切断。
  - 理由の文の数 ＝ 切断中で操作要素があるとき、閉じていれば 1、ダイアログが開いていれば 2。それ以外は 0。

## 状態遷移と Quint

切断・再接続でボタンの有効・無効とフォーカスが変わるのは状態遷移なので、Quint で仕様を書きました：`specs/quint/decision-offline-actions/`（`offlineActions.qnt`、`offlineActions_test.qnt`、README に範囲と検査の結果）。

- 遷移：切断、再接続、トリガーへのフォーカス、開く、ダイアログ内のフォーカス移動、確定（送信）、やめる、送信の結果。
- 不変条件：`noSendWhileDisconnected`、`focusNotOnDisabled`、`focusInsideOpenDialog`、`restoreWaitsOnlyWhileLocked`（上の 1・4・5 に当たる）。
- 結果：修正後（`fixed`）は `safety` を破らない（`quint run` 30 手 2 万件、`quint verify` 12 手）。修正前（`current`）は 3 手（切断 → 開く → 確定）で `noSendWhileDisconnected` を破る。筋書きのテスト 5 件が通る。
- 実物との対応：再接続の遅延（1 秒から倍々、上限 30 秒）はモデルに入れていない。`reconnect` はいつでも起きうる遷移として扱う。

## 壊しうる入力

- 境界：判断待ちが 0 件（ボタンが無いので変化なし）。値の欠けた項目（ボタンが無い、理由の文も出さない）。
- 並行：送信中に切断（送った分は結果を待つ。結果が返ってもトリガーは押せず、再接続でフォーカスが戻る。Quint の `settleWhileDisconnectedTest`）。確認を開いたあとで切断（確定だけ無効。e2e で確認）。切断と再接続が短い間に繰り返す（無効の条件が状態の関数なので、最後の状態に従う）。
- 再開：再接続で SSE の新しい状態が届き、一覧が入れ替わる。開いていた確認は、開いた時点の対象を保つ既存の仕組み（`decideDecisionTransition` の stale 判定）に任せる。
- 初期読み込みの失敗（`initialFailure` があり最初から切断）：最初から無効で、理由の文が出る。
- 長さ・Unicode・区切り・入れ子：文字列の扱いは変えていないので該当なし。

## 上流・保存済みデータ・公開 API・守りの仕組みへの影響

- 上流（takt、takt-mcp）：影響なし。
- 保存済みデータ：影響なし。
- 公開 API（proto、`/api/*`）：影響なし。変えたのは画面のコンポーネントの props だけ（`DecisionActions` と `DecisionActionsView` に必須の `disconnected` を足した。呼び出し元は `DecisionsContent` と既存のテストだけ）。
- 守りの仕組み（CI、関門、ルールセット）：影響なし。aislop の受け入れ一覧も変えていない。

## 確かめたこと

- 単体：切断中・接続中・開いたダイアログの 3 件と、上の性質のテスト。修正前のコードで、追加した 2 件が失敗することを確かめた。
- e2e：`e2e/tests/issue-307-disconnected-decisions.spec.ts`。`/api/state` を失敗させて開いている EventSource にエラーを伝え、確定が無効・見出しへフォーカス・やめるで閉じる・トリガーが無効・理由の文を確かめる。経路を戻すと再接続し、トリガーが押せてフォーカスが戻り、マージの書き込みは送られていない。修正前のコードで失敗することを確かめた。
